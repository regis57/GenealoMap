# GenealoMap - rules for anyone (human or AI assistant) changing this repository

## What it is

The name is **GenealoMap** (repository `regis57/GenealoMap`). It was first written "GeneanoMap" by mistake and renamed on 21 November 2026; do not bring the old spelling back. Browser storage keys (`cg.*`) do not contain the name and were not touched.

A static web page that plays a family tree on a map, year by year. Owner and author: Regis Hennequin (`regis57`). Licence: Apache 2.0 with `NOTICE`.

## Hard rules

1. **Privacy first.** A visitor's file never leaves the browser. No analytics, no remote font, no CDN, no cookie, no third-party request by default. Do not weaken the Content-Security-Policy in `index.html`.
2. **Three run-time files only**: `index.html`, `world.json`, `gaz.json`. No framework, no bundler, no npm dependency at run time. It must keep working when the three files are copied to any web folder. Two folders of data are optional and loaded on demand; the page must degrade quietly without them: `hist/` (borders of the time, GPL-3.0 data built by `tools/build-hist.mjs`) and `gaz/` (finer gazetteer by country, built by `tools/build-gaz.mjs`). `fetch()` may only name these files; `tools/check.mjs` holds the list. Offline use is optional too: `sw.js` (service worker, caches only the page, its data and `app/`, never a family file or a published tree) and `app/` (manifest and install icons, built by `tools/build-icons.mjs`); without them the page simply works online.
3. **File content is untrusted.** Everything coming from a GEDCOM/CSV goes through `esc()` before reaching `innerHTML`; links go through `safeUrl()` or the `https?://` patterns. Never `eval`, never inline event attributes, never `style="…"` attributes (use a class): the policy allows one script and one style block, each by fingerprint.
4. **After any change to the script**, run `node tools/check.mjs --fix`, then `node tools/check.mjs`, `node tools/test.mjs` and `node tools/browser-test.mjs` (the page driven in Chromium with fictional data, including a 20,000-person tree from `tools/make-big-tree.mjs`). CI runs all three and must be green. If a kinship title changes on purpose, review the difference and run `node tools/test.mjs --update`; never update the expected table to silence a failure you do not understand.
5. **Authorship.** Commits, pull requests and releases are authored by Regis Hennequin only. No "Co-Authored-By", "Generated with" or other AI/tool attribution in commit messages, PR descriptions or files.
6. **Never commit real family data.** A published tree (`?file=`) belongs on the owner's own host, never in this repository. The only people in the repository are the fictional Vernhet family (`SAMPLE` in `index.html`, `template.csv`). No real GEDCOM, no screenshot showing living people.
7. **Kinship must be true.** Blood relationship comes from the nearest common ancestor and generation counts; marriage is added to it, never substituted. By marriage, `kin()` goes as far as the blood relatives (within four generations) of the spouse of a blood relative, always naming the linking person; beyond that it says "no known relationship" rather than guess. No folk approximations ("à la mode de Bretagne"). Every term must exist in all languages of `KIN`. Where a language uses one word for two relationships (Dutch `neef`), the term says which.
8. **Every visible text is translated.** New interface text goes into `L` for every language of `LANGS` (`fr`, `en`, `de`, `it`, `es`, `pt`, `nl`, `lb`); no hard-coded string in the code. Names of historical states come from the data, in English; their translations live in `tools/hist-names.txt` (one line per name, all languages), turned into `hist/names.json` by `node tools/build-hist.mjs --names`. Names of peoples stay as written.
9. **Honest display.** Estimated dates carry `≈`, approximate positions are flagged, historical borders show their reference date with `≈` and uncertain ones are dashed; today's subdivisions are marked "current regions", and a historical region is added only if it is exactly a union of today's subdivisions. An exported image that leaves living people out says so. Never invent a person, a date or a place.
10. **Keep the docs in step**: `README.md` (features, roadmap), `FORMAT.md` (input formats), `PRIVACY.md`, `SECURITY.md`.

## Map of `index.html`

Sections, in order: i18n (`LANGS`, `L`, `KIN`, `term`) · fictional sample · state `S` · GEDCOM parser (`parseGed`, `loadGed`) · proofs and links · lives and locations (`computeLives`, `locAt`) · kinship (`blood`, `kin`, `titleOf`) · geocoding (`resolvePlaces`, `finerGaz`, `loose` for old spellings: last resort, same country, always `approx`) · year view (`setYear`, `evLine`) · map drawing (`frame`, `paint`) with historical borders (`HIST`, `histSnap`, `histFor`, `histName`), regions (`reg`, `drawRegions` for today's subdivisions, always labelled "current regions"; `drawHistRegions` for the dated unions of `tools/hist-regions.txt`, built by `tools/build-regions.mjs`) and the shareable view (`share`, `paintShare`) · map keyboard · timeline · panel (`renderPanel`, `personHtml`, `chronoHtml`) · search, file (`fileText`, `unzip`, `tarFile`, `xlsxRows`, `odsRows`, `grampsToGed`, `gwToGed`, both writing through `gedOf`), settings · table import (`rowsToGed`, `csvToGed`) · language and support (`applyLang`, `SUPPORT_URL`) · `boot`.

Page address options (`ARGS`): `lang`, `ref`, `year`, `theme`, `hist`, `play`, `file`, `living`; they are not stored. `file` is a tree published by the site (`pub`): bare file name in the same folder, living people hidden (`p.hid`) unless `living=1`; use `nameOf()` / `dispName()` whenever a person's name is displayed.

`S.ref` may be `null` (no reference person, saved as `cg.ref.<file>` = `none`): `kin()`, `titleOf()`, `tint()` and the tree must keep working without it, and nothing may interrupt or move the timeline when it is removed or restored.

Large trees: kinship colours come from sets computed once per reference (`kinSets`, `downFrom`), close relatives from a local walk (`near`), the year view lists at most 200 rows, the panel is redrawn at most four times a second while playing (`panelSoon`) and kinship titles are left out of rows and tree boxes until playback stops; the tree shows at most 250 boxes while playing (`treeMax`); the roots of the whole-family chart are computed once per file (`wholeTops`, `S.wt`). The finer gazetteer is indexed in slices of 20,000 names between frames, and the loose-spelling index of a country (`looseIx`) is built only when an exact search fails there. Keep these paths free of whole-tree loops per year.

Other pieces: colours (`tint`, `renderLegend`), routes (`routeOf`, `drawRoute`), tree view (`renderTree`; `tree.pref` is the chart of `#trMode`: `w` whole family (`wholeTree` from the oldest known ancestors, all generations, never trimmed by the year; spouses without known parents are named in their partner's box), `a`, `d`, `h` (`hourglass()`, mirrored `.th.rev` lists when horizontal), `f` (`fanSvg()`, SVG text, sectors by Sosa number, classes for colours, no style attribute); pressing the pressed button again returns to `w`; `tree.now` is the *Contemporaries of the year* box, which trims any chart to the living of the year plus the dead who link them (`treeEra` for `w`, the `trim` argument of `treeHtml`, `hourglass` and `fanSvg`); `tree.rootId` is the person chosen in the tree, a second click on them (`release`) or Esc lets them go; `treeNav` is the strip to move to parents, spouses or children; `fitGen` drops whole generations to stay under the box limit; `boxTitle` spends at most 40 ms per drawing on kinship titles; `treeShow` brings the chosen person, or else the first box, into view only if it is not already visible, and scrolls only `#tree`; below 1230 px the tree view is a column (timeline, tools, then the tree filling the rest; on phones the tools are one row that scrolls sideways), and a phone held sideways puts the panel beside it (`main.tview`, checked by the browser test at 390 and 900 px); `@media print` shows the tree alone and `beforeprint` zooms a wide tree to the page; without any person the four centred charts are disabled and a note says why), `setView`; nested lists drawn with CSS only, since no style attribute is allowed; address option `view=tree`). OpenStreetMap tiles need `referrerPolicy='origin'` (they are refused without a referrer).

Storage keys (browser only): `cg.ged`, `cg.name`, `cg.lang`, `cg.tiles`, `cg.hist`, `cg.theme`, `cg.route`, `cg.tint`, `cg.tree`, `cg.tpl`, `cg.manual`, `cg.ref.*`, `cg.custom.*`.

Offline: `offline()` registers `sw.js`; `HIST` in `sw.js` must equal `HIST` in the page (checked). Change the cache name `genealomap-N` in `sw.js` when its caching rules change.

Page icon: drawn in `tools/icon.svg` and embedded in `index.html` as data addresses (an SVG `rel="icon"` and a 180 px PNG `apple-touch-icon`), so no extra file is needed at run time. In the SVG address `http://` must stay percent-encoded, or `tools/check.mjs` reports an unexpected address.

## Working method

- Develop on a branch, run the check, test the page in a browser, then open a pull request to `main`, wait for the `check` workflow to be green and merge it. The owner has asked not to be consulted for these steps (decision of 21 November 2026): do them without asking. Ask only for choices that are his to make (licence, wording of public texts, anything irreversible outside this repository).
- Keep `README.md` and this file up to date in the same pull request as the change.
- Data folders are rebuilt with `tools/build-hist.mjs` and `tools/build-gaz.mjs`; never edit `hist/*.json` or `gaz/*.json` by hand.

## Publishing

`main` is served by GitHub Pages at https://regis57.github.io/GenealoMap/. The page keeps `noindex` during the test phase.

A second copy runs at https://regis-hennequin.info/genealomap/ (repository `regis57/regis-hennequin-site`, folder `public/genealomap/`). That site forbids anything inline, so its copy is the same page split into `index.html`, `app.js` and `app.css`; update it whenever `index.html` changes here, and copy `sw.js`, `app/`, `hist/` and `gaz/` with it.
